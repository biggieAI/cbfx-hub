Overview

Working Colorspace ACEScg (ACES AP1)    ACES Version 1.3    OCIO Config $OCIO

CBFX uses the Academy Color Encoding System (ACES) as its scene-linear, working colorspace. ACES provides a mathematically defined, device-independent color framework that preserves the full dynamic range captured on set, enables consistent looks across tools and artists, and maps cleanly to any delivery colorspace without round-trip errors. All VFX work — from CG renders to compositing to paint — must be performed in ACEScg unless an explicit exception is documented for the show.

The active OCIO configuration is resolved from the $OCIO environment variable. Never hard-code config paths in Nuke scripts or render jobs.

sRGB On-set monitor & comp work Default viewer transform for all comp work

Nuke Setup

  • Use OCIOColorSpace node for all colorspace transforms within the script
  • Use OCIODisplay node for the viewer output — never a plain Grade or LUT node
  • Set viewer transform to sRGB for general comp work; switch to Rec.709 when reviewing client deliverables
  • Never apply a display LUT to Read nodes — footage must enter the graph in its native log/camera colorspace and be converted via OCIOColorSpace
  • Confirm OCIO config version in Help > About matches the show's $OCIO path before starting any script

Environment Setup

export OCIO=/path/to/cbfx_aces_1.3/config.ocio

Add to your .bashrc / .zshrc, or set in the Nuke environment via nuke.env. Replace the path with the show-specific config location confirmed by the pipeline team.

What NOT To Do

  • Setting the wrong colorspace on Read nodes (e.g., leaving footage as "raw" or "linear" when it is camera log)
  • Baking a display LUT (sRGB or Rec.709 output transform) into EXR or DPX deliveries — always deliver scene-linear unless otherwise specified
  • Mixing ACES and non-ACES nodes in the same Nuke script without explicit conversion nodes between them
  • Using Nuke's default (non-OCIO) viewer LUT — always verify OCIODisplay is active
  • Copying OCIO config paths from old shows — always source the current show config from the pipeline team
  • Ignoring per-shot ACES IDT exceptions provided by the DIT — these override the table above
