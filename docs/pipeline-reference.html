SGTK Bootstrap

Run from the show root directory. The tank alias must be set up in your shell profile pointing to the show's tank executable.

Launch Nuke via SGTK
tank nuke_launch
Get ShotGrid context for current environment
tank shotgun_get_context

If the tank alias is not configured, add this to your shell profile, replacing <SHOW_ROOT> with your project path:

alias tank="Y:/PROJ/tank"

Nuke Paths

  • Gizmos: $NUKE_PATH/gizmos/ — custom gizmos loaded automatically on startup
  • Plugin path: Y:/pipeline/nuke/plugins — set via NUKE_PATH
  • Script templates: Y:/pipeline/nuke/templates/ — per-step starter scripts (COMP, ROTO, etc.)
  • Default Read path: $JOB/shots/$SHOT/plates/
  • Default Write path: $JOB/shots/$SHOT/$STEP/output/v###/<name>.####.exr
  • LUTs: $JOB/luts/ — project-specific LUTs, sourced from OCIO config

ShotGrid Publish Workflow

  1. 1
    Complete comp in Nuke. Ensure all write nodes have correct output paths and the script is saved.
  2. 2
    Run CompReview validation. All checks must pass before publish. Resolve any flagged errors.
  3. 3
    Execute tk-nuke publish from the File menu (File → ShotGrid → Publish…).
  4. 4
    ShotGrid version created automatically. CompReview links the version to the active SG context without manual entry.
  5. 5
    Supervisor notified via ShotGrid notification. No manual ping required.

Deadline Submit Checklist

  • Correct pool selected — use gpu-pool for GPU renders, cpu-pool for comp/cache tasks
  • Frame range matches shot — verify against cut sheet or ShotGrid before submitting
  • Output path uses $JOB tokens — avoid hardcoded drive letters; use environment variable paths
  • Chunk size: 10 frames for comp jobs, 1 frame for simulation jobs
  • Priority set appropriately: 50 Normal 75 Rush 90 Emergency
  • LocalBurn v2.3.1+ installed and selected as the submit plugin — ensures frame range override works correctly
